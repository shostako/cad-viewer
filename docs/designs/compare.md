# 版の比較（#47 項目 8、#59 P2）

2026-10-12。お客さんから届いた改訂版を、前の版と重ねて、足された所と削られた所を色で見る。#59 の P2「改訂比較を実務で使える形にする」の最初の段で、同じ座標系にある 2 つの版を比べる。位置合わせ（ずれた座標系）と、変わった所の一覧・記録は、その次の段にする。

## ほかの製品はどうしているか

| 製品 | 比べ方 | 見せ方 |
| --- | --- | --- |
| SOLIDWORKS の Compare Geometry | 体積の比較：2 つの体をブーリアンで引き算し、「削る材料」「足す材料」「共通の体積」を出す。面の比較：片方にしかない面と、少し違う面（重なりが小さい方の面の 50 % を超える）を分ける | 体積は色の付いた体で、それぞれ出す・隠すを切り替える。面は、片方だけの面を赤、少し違う面を黄、同じ面は元の色 |
| Autodesk Docs（Version Compare）、Viewer の DiffTool | 物（要素）ごとに、足された・消えた・変わった | 3 つのふるいを入り切り。色は製品で違い、足されたを緑、消えたを赤、変わったを橙・黄にするものが多い |
| 3D_Analyzer、MagicCheck、3DViewStation（市販の比較・検査のソフト） | 面と面の離れ（偏差） | 部品の上の色の地図。0 を中心にした対称な色の帯 |
| CloudCompare（点群・メッシュ） | 最も近い点までの距離。符号は三角形の法線の向き | 対称な色の帯を両方に同じに当てると、どちらが出ているかが見える |

- SOLIDWORKS: [Compare Geometry の options](https://help.solidworks.com/2025/English/swconntutorial/t_comparegeomoptions_utilstut.htm)、[CATI の解説](https://www.cati.com/blog/solidworks-free-tools-utilities-compare-geometry/)
- Autodesk: [DiffTool](https://aps.autodesk.com/en/docs/viewer/v7/developers_guide/viewer_basics/difftool)、[Revit の版の比較](https://help.autodesk.com/cloudhelp/ENU/BIM-360Team/files/GUID-EF7ABDC0-1BE9-47AD-AC1C-998247093778.htm)
- [CloudCompare の Cloud-to-Mesh Distance](https://www.cloudcompare.org/doc/wiki/index.php/Cloud-to-Mesh_Distance)

## この app でどうするか

**面の離れの色**にする（ブーリアンはしない）。

- 欲しいのは「どこが」「どちら向きに」「どれだけ」変わったか。偏差の色の地図は、この 3 つを一度に見せる。
- ブーリアンは、2 つの版で大半の面が重なる（変わっていない面）という、OCCT がいちばん苦手な組み合わせになる。時間がかかり、落ちることがある。STL などのメッシュの形式には使えない。
- 体積の増減（重さの変化）は、それぞれの版の体積・重量の差で見られる（今もある）。

### 何を測るか

- 2 つの版のそれぞれの表面の点から、相手の版の表面までの、いちばん近い距離。点は表示用のメッシュの上に取る。肉厚と同じく、B-rep の真値ではなく、表示用メッシュの上の目安とする。
- **符号は「足された（＋）」「削られた（−）」に読む。** 新しい版の表面の点が前の版の外にあれば、そこに材料が足された（＋）。中にあれば、削られた（−）。前の版の表面の点は逆に読む（新しい版の外に出ていれば、その材料は削られた）。
  - 内か外かは、相手の版のいちばん近い点の、外向きの法線で決める。そこに集まる三角形の法線を、その点での三角形の角度で重み付けして足す（Baerentzen と Aanaes の角度で重み付けした擬似法線）。いちばん近い点が三角形の中でも、稜線や角の上でも、外向きを正しく指す。
    - 三角形の数で数えると、鋭い稜線（90° より鋭い）の端で、三角形の多い面に引っぱられて取り違える（単体のテストのくさび）。
    - 三角形は、頂点の共有ではなく、場所で集める。B-rep の表示用メッシュは面ごとに頂点を持つので、稜線の両側の面は頂点を共有しない。
    - 最初はレイを飛ばして横切る数の偶奇で決める案だった。それだと、曲面の継ぎ目の髪の毛ほどの隙間を通ったレイが数え違える。点ごとにレイを 3 本飛ばす重さもある。
  - 相手の部品が閉じていない（面だけの形）ときは、内も外も無い。そのときの符号は「相手の面の表側か裏側か」になる。凡例には書かない（今の段では、閉じた部品を前提にする）。
- **頂点だけでなく、面の中でも測る。** 頂点だけだと、平らな面の頂点は縁にしかないので、たとえば埋めた穴が見えない（穴の内壁の頂点は、相手の上面と下面の上に乗るので、離れが 0）。三角形を、辺の長さが部品の大きさの 1/150 以下になるまで細かく割り、その頂点で測る。色もその細かいメッシュに塗る。
- **許容**：これより小さい差は「変わっていない」（灰色）とする。
  - 曲面の表示用メッシュは弦で近似していて、真の面から粗さ（100 mm の部品で 0.1 mm ほど）だけ離れる。2 つの版で同じ曲面でも、その分だけ離れて見える。
  - なので、許容の初めの値は 2 つの版の粗さの大きい方にし、画面に「これより小さい差は見分けられない」と出す。平らな面とメッシュの形式（STL など）にはこの誤差が無い。
  - 小さい差を細かく見たいときの道（比べる所だけ細かくテッセレーションし直す、B-rep で測り直す）は、次の段で考える。

### どこで計算するか

ブラウザの中（Worker）で、手元の版と Web 版の両方とも同じ `compare.ts` で計算する。backend には足さない。

- 2 つの版の表示用メッシュは、どちらの版でもブラウザに届いている。いちばん近い点は three-mesh-bvh（肉厚の Web 版と同じ）で速い（1 点に数マイクロ秒）。
- backend と Web 版の 2 つに書いて突き合わせる手間が要らない。答えは 1 つの実装から出る。

### 見せ方

- 「版の比較」のフォルダに「別の版と比べる…」。開いている版はそのまま、もう 1 つのファイルを読む（STEP・IGES・STL など 3D の形式。図面は比べない）。
- **「新しいのは」で、開いている版と比べる版のどちらが新しいかを選ぶ。** 初めは「開いている版」（届いた新しい版を開いて、手元の前の版と比べる流れ）。
- **見せ方**
  - 重ねる：新しい版を色付きで出し、前の版は削られた所だけを半透明の赤で重ねる。消えたリブのように、新しい版に面が無い変更も、そこに見える。
  - 新しい版だけ、前の版だけ：その版の全部の面に色を塗る。
- **色**：足された所は青緑、削られた所は赤橙、許容の中は灰色。差が大きいほど濃い。
  - 赤と緑は、色覚の多い型（2 型・1 型）で見分けにくい。そこで、青寄りと黄寄りの対にした。凡例には、色の意味を文字でも書く。
  - 色の帯の端は、差のいちばん大きい所。凡例に出す。
- 比べている間は、開いている版の面を隠し、比較の色の面を出す。断面は、比較の面も切る。
- カーソルの下には、その点の差を出す（「足された +1.20 mm（新しい版の面）」）。色と同じ値を、同じ細かいメッシュから読む。
- 計測・注記のモード、肉厚のヒートマップ、抜き勾配の色分けを入れたら、比較はやめる。どれも開いている版の面の上の物で、比べている間は、その面を隠しているからだ。新しいファイルを開いたときも、比較はやめる。

## 段

1. **この PR**：別の版を開く、色の地図、重ねる・片方だけ、許容、凡例、カーソルの下の値。テストは 2 つ。
   - `compare.ts` の単体（作り方の分かっている形で、距離と符号と細かい割り方。鋭い稜線の符号）
   - E2E（テストデータの 2 つの版の、足された・削られた・変わらない所の画素の色。許容、入れ替え、断面、カーソルの下の値）
2. 変わった所の一覧（問題の一覧と同じく、所ごとにまとめ、押すと寄る）と、確認の記録への書き出し。→ 凡例の「変わった所へ」と記録の「版の比較」の表で作った。所は、足された所を新しい版の面の上で、削られた所を前の版の面の上で数える（同じ変わり目を 2 回数えない）。
3. 位置合わせ（手で選ぶ基準の点・面から）と、剛体のずれと形の変更の区別。
