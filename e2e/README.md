# E2E テスト（Playwright）

前提: uvicorn (port 8008) と Vite dev server (port 5183) が起動済みで、`testdata/` に素材があること。
素材は生成物で git には入っていない（`test_iges_sewing.py` の IGES と `test_png_export.py` の `colours_drawing.dxf` は、無ければテストが backend の venv で自分で作る）。

```bash
# 素材の生成（backend の venv で。OCP を使う）
backend/.venv/bin/python testdata/make_testdata.py       # ribbed_plate.stl
backend/.venv/bin/python testdata/make_step_assembly.py  # mini_mold.step
backend/.venv/bin/python testdata/make_dxf.py            # plate_drawing.dxf, colours_drawing.dxf
backend/.venv/bin/python testdata/make_iges_loose.py     # loose_faces_box.igs

# サーバ起動
(cd backend && .venv/bin/uvicorn app.main:app --reload --port 8008) &
(cd frontend && npm run dev -- --host 127.0.0.1 --port 5183 --strictPort) &

# 実行（システム Python の playwright を使う。各スクリプトは独立している）
for t in e2e/test_*.py; do python3 "$t" || echo "FAILED: $t"; done
```

接続先を変えるときは `CAD_VIEWER_URL` で上書きする（既定 `http://127.0.0.1:5183`）。

注意:
- ヘッドレスChromium(SwiftShader)ではlil-gui付近に白矩形のWebGL合成アーティファクトが出る（実ブラウザでは出ない）
- 計測・注記・サイドカー系のテストは共有の backend のサイドカー（`backend/.sidecars/`）に書き込む。そこには手元で開いた実データの計測・注記も入るので、ディレクトリを丸ごと消さない。後片付けはテストデータの分だけにする（ファイル名は中身の sha256 の先頭 32 文字）:
  `for f in testdata/*.step testdata/*.stl testdata/*.dxf testdata/*.igs; do rm -f "backend/.sidecars/$(sha256sum "$f" | cut -c1-32).json"; done`
- テストは `window.__cadProject` / `__cadPick` / `__cadView` フック（main.ts）でワールド座標からクリック位置を決定論的に導出し、カメラの状態を読む（`__cadView` は near / far と、投影 `projection`（`'perspective'` / `'orthographic'`）・`zoom`（平行投影では見えている高さの半分が 1 / zoom、透視では常に 1）も返す。near / far と位置は使っている方のカメラのもの）
- `test_nav_fit.py`（全体表示）・`test_nav_fit_panels.py`（全体表示がパネルを避ける）・`test_nav_fit_shape.py`（全体表示の範囲をモデルの形で選ぶ）・`test_nav_wheel.py`（ホイールの拡大縮小）・`test_nav_pivot.py`（ダブルクリックの回転の中心）は、共通の部品を `nav_common.py` から使う。検査用の箱の STL は一時ディレクトリに書いて使い、最後に消す。mini_mold.step は末尾に改行 3 つを足した自分専用のコピーを一時ディレクトリに作り、始めに API でそのサイドカーを空にする（ほかのテストが共有の mini_mold.step に残した注記は計測の一覧として戻り、全体表示はそれを避けるので、モデルの大きさと位置が変わってしまう）。1 本にまとめると CI の 1 本あたりの打ち切り（当時 300 秒、いまは 600 秒）を超えたので分けてある。1 本は目安 2 分以内（手元で）に収める
- 全体表示の検査の基準（`nav_common.py` の `free_rect`）: パネル（`PANELS`: 操作パネル・部品ツリー・左下の案内・計測の一覧・体積・重量・左下の座標軸）の `getBoundingClientRect` から、どのパネルにも重ならない長方形（幅と高さが canvas の 4 割以上）の候補を出す。その中でいちばん広いもの（同じ広さなら中心が canvas の中心に近いもの、次に左、次に上が小さいもの）を使う。ただし、モデルの箱を全体表示の向きから見た幅 w・高さ h に対し、min(長方形の幅 / w, 長方形の高さ / h)（モデルの映る大きさ）がいちばん広いものの 1.1 倍（`SWITCH_GAIN`）以上になる候補があれば、それがいちばん大きいもの（同じなら広さ、中心、左、上の順）を使う。候補が無ければ canvas 全体とする。向きは `Nav.load`・`Nav.fit`・`Nav.mark_fit` が記録したカメラから取り、モデルの箱は検査に渡した箱か、ファイル名から分かる箱（`KNOWN_BOXES`）を使う。箱の角の投影がその長方形の 0.86〜0.90 を占め、真ん中にあり、どのパネルにも重ならないことを確かめる。アプリの実装（`frontend/src/freearea.ts`）とは別に書いた同じ規則で、期待値をアプリから取らない
- 全体表示はその瞬間のパネルを読むので、検査はその瞬間に記録したパネルの矩形を使う。全体表示は `Nav.fit()`（lil-gui のフォルダの開閉の動き 300 ms が終わるのを待ってから押す）か `Nav.load()` で行い、検査までにパネルが変わっていたら失敗にする。`needs=` を付けた検査は、そのパネルを無視した正しい全体表示なら落ちることも確かめる（そのパネルを試せていない検査を見逃さないため）
- 読み込みは体積・重量の値を少し（頼んでから 1.5 秒まで）待ってから全体表示する。`Nav.load()` はこの待ちを時間に左右されないようにする（`props=`）。既定の `"frozen"` は値を `window.__cadStallProperties` で止め、`window.__cadPropsWait(0)` で待たせない（全体表示のときも検査のときも「計算中…」）。`"live"` は値を通し、いくらでも待たせる（全体表示のときに値が出ている）。`"late"` は値を止め、アプリ自身の待ちのまま（待ちが切れたら「計算中…」で全体表示する）
- 画面にパネルを足したときは、`frontend/src/main.ts` の `FIT_PANELS` と `nav_common.py` の `PANELS` の両方に足す
- `test_nav_fit_panels.py` は、細長い箱（STL）、面がバラバラの IGES（短い部品ツリー、体積・重量の値あり。パネルの幅はテストの CSS で 330 px 以上に固定してフォントの差に左右されないようにする）、mini_mold.step の自分専用のコピー（末尾に改行 5 つ。注記 12 個で計測の一覧を長くする）を使い、ウィンドウの大きさ（1280×800・700×1100・450×900・400×900。全体表示のあとで幅を 1000・300 に変えて、表示の中心のずれが px のまま保たれ、幅の 3 割で止まることも見る）とフォルダの開閉（視点・表示・操作パネル全体）を変えて確かめる
  - 体積・重量: 値が来ない（`"late"`。待ちが切れて「計算中…」で全体表示する）、値が間に合う（`"live"`。全体表示が値の出たパネルを避ける）、操作パネルを畳んだ細長い箱（値の出たパネルが空き範囲の下端を決める）
  - 読み込み直しは別のモデル（細長い箱）から始め、`page.route` でサイドカーの取得を 0.3 秒遅らせる。毎フレーム、カメラの位置と、型の板の上の点の投影で `__cadPick` が型に当たるか（型が描かれているか）を記録し、型が最後の位置以外で描かれたフレームも、前後どちらでもない位置のフレームも無いこと（読み込みの全体表示は 1 回だけ）を確かめる
  - サイドカーの異常: labelPos の無い注記を良い注記 2 つのあいだに入れる（良い 2 つが戻り、悪い 1 つは印も描かれず、左下の案内に「1 件を復元できなかった」）。サイドカーの取得が JSON でない本文を返す（計測なしで開き、案内にそう出す）。backend が保存ファイルの壊れを 500 と理由で返す（同じく開き、案内に理由が出る。ブラウザがコンソールに出す 500 の行だけは許す）。どちらもモデルは開いて全体表示され、部品ツリーと体積・重量のパネルも出る
- `test_nav_fit_shape.py` は 1280×800 で mini_mold を正面と上から見て全体表示する（透視と平行の両方）。部品ツリーの大きさをテストの CSS で 180×170 px に固定し、映る大きさの比がフォントに左右されないようにする。正面ではツリーの下の横長の範囲が約 1.23 倍大きく映るのでそちらを使い、上からでは約 1.05 倍（1.1 倍未満）なのでいちばん広い範囲のままにすることを確かめる。どちらも、もう一方の決まり（いつもいちばん広い範囲、いつもいちばん大きく映る範囲）の全体表示なら同じ検査で落ちることも確かめる
- `test_nav_fit.py` の A11 は、2D 図面を出しているあいだにウィンドウの大きさを変えてから 3D を開き、読み込みの全体表示が新しい大きさで行われることを確かめる。3D の canvas が新しい大きさに追いつく（ResizeObserver が知らせる）のがメッシュの到着の前か後かは時間で決まるので、大きさを 4 通り変えて繰り返す。それでも後になる回は少ないので、A12 で時間に頼らずに確かめる: 1 回の `page.evaluate` の中で `#viewport` の大きさを style で変え、同じタスクで F の keydown を送る（ResizeObserver は次のフレームまで知らせないので、全体表示は必ず知らされる前に走る）
- `test_properties.py`（体積・重量のパネル）は `/properties` を持つ backend が要る。mini_mold.step は末尾に改行 9 つを足した自分専用のコピーを使い、始めに API でそのサイドカーを空にする（ほかのテストが共有の mini_mold.step に残した計測が戻ると、計測の一覧が長くなり、パネルの配置の検査が別のものを見てしまう）。`window.__cadStallProperties(ms)` で次の 1 回の取得を遅らせ、古い応答を捨てることを確かめる（このときは `window.__cadPropsWait(0)` で読み込みに値を待たせず、すぐ「計算中…」を出す）。同じ仕組みで「計算中…」（部品ごとの表が無い）にしておき、計測の一覧がスクロールし始めるときに、一覧の上端が操作パネルのすぐ下（8 px）にあること（表の分の場所を空けていないこと）を、高さ 800 px の窓で確かめる。このときは mini_mold.step の末尾に改行を 13 個足した自分専用のコピーを使い、作った計測は最後に消す
- `test_measure_undo.py`（計測と注記を失わない）は、mini_mold.step で計測 3 件（距離・円筒の ⌀・距離）を作り、「計測クリア」と × のあとの［元に戻す］と Ctrl+Z で、消す前と同じ文・同じ順に戻ることを確かめる。戻せる時間（8 秒）が過ぎたとき・ほかの計測を足したとき・別のファイルを開いたときは戻らないこと、Esc で 1 点目を取り消し（3D と 2D の図面）、もう一度の Esc でモードが「なし」になること、注記の入力欄はほかの所のクリックで確定し Esc で捨てること、入力中に別のファイルを開くとその注記が元のモデルに保存されること、2D の図面の「計測クリア」も戻せて、新しい計測で戻せなくなることも見る。サイドカーは `page.route` で受け、保存された中身（PUT の本文）で自動保存が戻した一覧を書くことも確かめる
- `test_hide_panels.py`（パネルを隠す）は、画面の右半分（767×639）で mini_mold.step の自分専用のコピーを開き、H でパネルが消えて全体表示が収め直されること（期待値は `nav_common.free_rect` の空き範囲。消したあとの範囲には「パネルを出す」も入る）、モデルの幅が 1.3 倍より大きくなること、状態表示が 1 行のままであること、もう一度 H で元の大きさに戻ること、視点を動かしたあとは収め直さないこと、ボタンでも切り替わり操作パネルのフォルダの開閉は変わらないこと、注記の入力欄では h が文字として入ること、2D 図面でも切り替わることを確かめる
- `test_view_modes.py`（空の画面の案内、2D 図面で 3D 用の項目を隠す）は、メッシュの取得をわざと失敗させる（`page.route` で中断）ことで、前のモデルを片付けたあとの失敗で案内が戻ることを確かめる
- `test_display_styles.py`・`test_display_styles_more.py`（表示スタイル）は、共通の部品を `display_common.py` から使う。窓は 1700×1050（全体表示はパネルの空き領域に収めるので、1280×800 では型が小さく映り、見る点と稜線の間隔が足りない）。mini_mold.step は末尾に改行を 11 個足した自分専用のコピーを一時ディレクトリに作って使う（別のモデル id とサイドカーになる。共有の backend では `test_section_annotation.py` が mini_mold のサイドカーに注記を残すので、そのままだと目印の球と札が画面と書き出しに入る）。読み込むたびに、計測の一覧が空であることを確かめる。期待値は、作り方の分かっている形状（板・ピン・ブロック、テストが書く STL の壁と箱）の `__cadProject` の投影、`__cadPick`、`__cadView`（`displayStyle` も返す）、仕様の色（背景、計測の目印、線だけの部品の琥珀色）、canvas の画素から出す。画素を見る点は、投影した B-rep の稜線（隠れた稜線も。ワイヤーフレームでは見える）から 10 px 以上離し、稜線に沿って見る帯は、ほかの稜線から 8 px 以上離す（どちらも実行時に確かめる）。`window.__cadRenderInfo()`（WebGL のジオメトリとシェーダーの数、直前のフレームの描画の回数）で、切り替えでジオメトリを作らないこと、半透明で描画の回数が増えないことを確かめる。切り替えの後に前のスタイルの設定が残らないことは、各スタイルの最初の画面（同じ視点）を取っておき、ほかのスタイルを逆順・順に回したあとと、全部の検査のあと（ヒートマップ・断面・部品の非表示・書き出しのあと）に、画面全体が同じ（各画素の差 2 以下）であることで確かめる。IGES では、各スタイルを選んでから開き直した画面（まだ何も切り替えていない状態）を基準にして、同じことを確かめる。ワイヤーフレーム・半透明で、ブロックの奥のピンの稜線（描いている線）の上をクリックするとその稜線を取り、案内に部品の名前が出ることも確かめる（その点はほかの線から 12 px、頂点から 16 px 以上離す）。クリックする点（ピック）は、ほかの部品の線から 12 px 以上離す（10 px 以内だと線を取るため）。断面のキャップは、半透明で初めて作ったとき・キャップを入れ直したときも同じ見え方であること、切り口の外（キャップの面の上で、奥に何もない点）には描かないこと（背景の色のまま）を確かめる。キーボードでは、表示スタイルの選択に焦点があっても（選んだ直後も）矢印は視点を回し、スタイルを変えないことを確かめる（操作パネルのほかの選択欄と同じ規則）。STL は一時ディレクトリに書き、IGES（`loose_faces_box.igs`）は `test_iges_sewing.py` と同じく無ければ作る。`cad-viewer:view` は始めと終わりに消す。写真は `/tmp/cad_viewer_display_styles*.png` に残る
- `test_png_export.py`（画像を保存）は、devicePixelRatio 2・時間帯 Asia/Tokyo のブラウザで、Playwright のダウンロードの仕組みで PNG を受け取り、画素を調べる。mini_mold.step は末尾に改行を足した自分専用のコピーを一時ディレクトリに作って使う（別のモデル id とサイドカーになり、共有の backend のサイドカーに触れない）。DXF は `plate.drawing.dxf` という名前のコピーで、ファイル名の規則（最後の拡張子だけを除く）を確かめる。`colours_drawing.dxf`（WIPEOUT と黄・シアンの線と文字）で、白の書き出しの色の扱いを確かめる。途中で CDP の `Emulation.setDeviceMetricsOverride` で devicePixelRatio を 1 にし（倍率の違うモニターへの移動に当たる）、画面の canvas と画像の大きさが付いてくることを確かめて 2 に戻す。期待値は、画面に出ているフレーム（canvas の toDataURL）、`__cadProject` の投影、ezdxf の背景の矩形からの DXF→SVG の対応、パネルとラベルの矩形、ラベルの中の語の DOM の範囲、白との明暗の比（WCAG の相対輝度）から出す。保存した PNG は `/tmp/cad_viewer_png_*.png` に残る
